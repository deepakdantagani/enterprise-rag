# Project Working Rules

- Ask for clarification before acting when less than 95% confident about the user's intent or requirements.
- Be honest about uncertainty, mistakes, and results. Clearly distinguish verified facts from assumptions and untested work.
- Push back respectfully when an approach seems incorrect or counterproductive. Explain the concern and suggest a better alternative.
- Do only what is necessary for the current agreed goal. Do not add unrelated features, code, or tasks.
- Keep every PR very small, focused on one purpose, and simple enough for the user to understand and review easily.
